# AffiKeep Pro ロードマップ

最終更新: 2026-07-08
関連仕様: [`PRO_SPEC.md`](./PRO_SPEC.md)

現状 v0.4.3 → 以下のフェーズ順で実装する。各フェーズは独立してリリース可能な単位とし、フェーズ0（基盤整備）以外は無料版ユーザーに影響を与えない追加実装とする。

## フェーズ0: 基盤整備（v0.5.0）

目的: Pro機能を安全に追加できる土台を作る。ユーザーから見える変化は「設定画面にProライセンス欄が増える」程度に留める。

- [ ] `AffiKeep_License` クラス実装（`includes/class-license.php`）
  - オフラインキー検証、有効化ボタン、ステータス表示
  - 期限切れ7日間のグレースピリオド
- [ ] `AffiKeep_Malls` レジストリ実装（`includes/class-malls.php`）
  - 既存3モール（amazon/rakuten/yahoo）を移行
  - `class-settings.php` / `class-link-checker.php` の switch文をレジストリ参照に置き換え
- [ ] 手動キー発行の運用フロー整備
  - Stripe決済リンク作成
  - 購入後にキーを手動発行・メール送付する手順をドキュメント化
- [ ] Pro判定ヘルパー（`AffiKeep_License::is_active()`）を各所から呼べる状態にする

**完了条件**: 無料版として現状のリグレッションが無いこと（既存の全機能が今まで通り動作）。ライセンスキーを入力すると設定画面に「Pro: 有効」と表示されること。

## フェーズ4: バックログ（着手時期未定）

以下は今回のロードマップの対象外。需要が顕在化した時点で改めて仕様化する。

- 課金基盤のFreemius/EDD移行（自動決済・自動アップデート配信・ライセンス有効化数の制御）
- リンクチェックの高速化・優先実行（時間単位実行、全件即時チェックの高速化）
- チーム機能・複数サイトライセンス管理

## リリース・検証方針

- WordPress依存が強いプラグインのため、ユニットテストよりも実環境（ステージング/本番相当のWordPress）での動作確認を優先する。
- フェーズ0のモールレジストリ化は既存の無料機能に触れるリファクタのため、他フェーズより慎重に回帰確認を行う（リンク切れ判定・アフィリエイトURL変換が今まで通りの挙動になっているかを重点確認）。
- 各フェーズ完了後、`AFFIKEEP_VERSION` / `AFFIKEEP_BUILD` を更新し、既存のバージョン管理慣習（コミットメッセージに `vX.Y.Z: 変更概要` を記載）を踏襲する。
